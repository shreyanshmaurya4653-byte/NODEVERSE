Features Announcement

Everything you need to
automate at scale

A comprehensive set of tools to build, run, monitor, and recover complex automation workflows.

Visual Workflow Builder

Drag-and-drop nodes for manual/webhook triggers, HTTP requests, transformations, delays and conditions. Design complex automation flows visually.

DAG Canvas Drag & Drop React Flow

Cycle Detection & Validation

Automatic cycle detection prevents invalid graphs before saving or running. Required node settings are validated upfront.

Webhook & Scheduled Triggers

HTTP endpoints start event-driven runs. Cron schedules start time-based runs with configurable payloads.

Distributed Task Processing

BullMQ-backed queues with separate worker processes ensure API traffic is not blocked by long-running nodes.

Execution History & Telemetry

Full run status per node, timestamps, context inputs, outputs and errors are auditable and actionable via logs.

Retry, Idempotency & Dead-Letter

Configurable retry caps, exponential backoff with jitter, duplicate-execution guards and visibility into exhausted failures.

Live Streaming Execution View

Server-Sent Events (SSE) stream real-time status updates and streaming output to the canvas while a run is in progress. Watch your workflows execute node-by-node.

Process Flow

Six steps from idea
to automated reality

01

Design

Build the workflow on the visual canvas by adding nodes, configuring them and connecting dependencies.

02

Validate

Check required node settings and detect cycles before a workflow is saved or run.

03

Trigger

Start a run manually, through an incoming HTTP webhook, or from a configured schedule.

04

Execute

Calculate a valid topological order and run each node only after its parent nodes succeed.

05

Observe

Store run and node status, inputs, outputs, timestamps and errors; stream updates to the canvas.

06

Recover

Retry eligible failures using configured limits and backoff; send exhausted failures to a dead-letter queue for review or replay.

System Architecture

Built for reliability
and scale

A layered architecture separating concerns across client, execution, and trigger planes.

CLIENT
React + Vite → React Flow → Express REST API
DATA + EXECUTION
PostgreSQL → Redis + BullMQ → Worker Processes
TRIGGERS + LIVE VIEW
Webhooks → Cron Scheduler → SSE → Canvas Updates

React + Vite Canvas

Component-based frontend with hot-reload. Keeps the interface snappy and development cycle rapid with a full-fat framework.

React Flow Engine

Provides canvas interactions such as nodes, edges, pan and zoom. Implements graph validation and execution logic before adopting a message-workflow engine.

Node.js + Express

Lightweight REST API and webhook layer using the server language ecosystem as the toolset, suitable for routing, validation and integration without framework overhead.

PostgreSQL

Durable relational storage for workflow definitions, run and node results, with constraints and transactions to protect state consistency compared with in-memory storage.

Redis + BullMQ

A Redis-backed queue for asynchronous jobs, concurrency, retries and worker coordination; more resilient and scalable than running all tasks within a single API process.

Server-Sent Events

Simple one-way stream to the browser for live run updates. Better fit for NODEVERSE than WebSockets where the canvas only needs to receive live status events.

Technology Selection

Carefully chosen
technology stack

Every library selected for a precise reason — performance, reliability, and developer experience.

Library / API Why It's Selected
React + Vite Component-based frontend and hot-build tooling. Keeps the interface modular and the development cycle rapid with a familiar full-stack framework.
React Flow Provides canvas interactions such as nodes, edges, pan and zoom. The team will implement its own graph validation and execution logic rather than adopting a message workflow engine.
Node.js + Express A lightweight REST API and webhook layer using the same language ecosystem as the frontend, suitable for routing, validation and integration without framework overhead.
PostgreSQL Durable relational storage for workflow definitions, run and node results, with constraints and transactions to protect state consistency compared with in-memory options.
Redis + BullMQ A Redis-backed queue for asynchronous jobs, concurrency, retries and worker coordination; more resilient and scalable than running all tasks within a single API process.
Cron Scheduling A cron-parser library will schedule and maintain trigger runs in due time. The exact package will be selected after checking maintenance, issue activity and license compatibility.
Server-Sent Events (SSE) A simple one-way server stream to the browser for live run updates. It is a better fit than WebSockets where the canvas only needs to receive live status events.
Docker Compose Coordinates the API, database, Redis and worker services in a reproducible local demo environment, avoiding manual or error-prone startup setup.
